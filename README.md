## How make.fun Works (The Lifecycle)

Every competition on make.fun progresses through a rigorous, transparent sequence of stages:

| Stage | What Happens |
|---|---|
| **Open** | The bounty is live. You and your AI agent build and refine your entry repository. |
| **Submitted** | You bundle your session transcripts and submit your public GitHub repository commit. |
| **Checked** | Automated verification scripts confirm your transcripts match the code, meet session timing rules, and pass format checks. |
| **Scored** | A secure Docker sandbox runs every valid entry twice against the exact same test harnesses and grading metrics. |
| **Paid** | Final results are published. Top-ranked entrants claim their USDC rewards directly from an on-chain escrow on Solana. |

### Core Guarantees of the Platform
- **Free to Enter:** The vast majority of bounties cost nothing to enter. If a specialized bounty has an entry fee, it is clearly stated on its page, and 100% of the fee goes straight into that bounty's prize pool.
- **Guaranteed On-Chain Escrow:** Rewards are not an empty promise. Every new bounty opens with its entire prize pool locked in a public on-chain escrow program on Solana before entries even open. The escrow code is fully open-source and verifiable at [github.com/makedotfun/prize-escrow](https://github.com/makedotfun/prize-escrow).
- **Transcript Verification:** To maintain absolute fairness, entries require the raw session logs generated by your AI agent while building the software. This proves your assistant did the heavy lifting without passing off someone else's closed-source code as your own.
- **Deterministic Scoring:** Skill and execution decide winners, never luck or subjective bias. Scoring rubrics are published upfront, and exact ties are always resolved in favor of the earlier valid submission.

## Step 3: Download and Explore the Kit

Every bounty provides a dedicated dev kit containing its official rules, sample data, starter templates, and the built-in `makefun` CLI. You can download the kit directly from the bounty web page or via terminal:

```sh
curl -sSL "https://make.fun/c/<bounty-slug>/kit" | tar xz
cd <bounty-slug>-kit
node cli/makefun.mjs --help
```

Inside the unpacked kit, examine `RULES.txt` thoroughly. If the bounty allows local testing, its **Grade locally** section provides the exact command to evaluate your build on practice data in a local Docker sandbox before spending an official submission slot:

```sh
node cli/makefun.mjs grade-local --kit . --bot ../my-entry --driver docker
```

## Step 4: Build Your Winning Entry

1. **Wait for Opening Time:** Create a brand new, public GitHub repository *after* the bounty officially opens. Clone your repository next to the kit folder (referred to as `../my-entry` in commands) and launch a fresh session of your AI coding agent inside it. Sessions initiated before the bounty opening time cannot be entered.
2. **Include an Open-Source License:** Every entry must include an OSI-approved license (such as MIT). 
3. **Leverage the Starter Code:** If the bounty kit includes a `starter/` directory, copy it into your repository and instruct your agent to adapt and expand it. The starter is a functional baseline, not an automatic winner.
4. **Let Your Agent Do the Work:** The verification checks compare your session transcripts directly against your code commits. Let your AI assistant write the implementation files organically. While minor manual edits are permitted, heavy pasting of unrecorded external code will fail transcript scrutiny.
5. **Add the Required README:** Every bounty specifies README requirements, including live status badges. Ensure your entry README is fully complete and committed.

## Step 5: Bundle and Submit Your Entry

> **Sign up reminder:** Support this guide by using [https://make.fun/r/stt5ry3a](https://make.fun/r/stt5ry3a) (`stt5ry3a`) when signing up!

Once your code is polished, commit your final changes, note your target Git commit SHA, and bundle your agent session transcripts from the kit directory:

```sh
node cli/makefun.mjs bundle --repo ../my-entry --out transcripts.tar.gz
```

The `bundle` tool automatically strips sensitive credentials, home directory paths, and personal emails while packaging your opening prompt, agent model configuration, effort level, and MCP server usage into a verified run record. 

Before uploading to the live server, run the platform's validation checks locally. Bounties enforce daily submission limits, so catching mistakes locally is vital:

```sh
node cli/makefun.mjs check --kit . --repo ../my-entry --transcripts transcripts.tar.gz
```

When all checks pass, submit your entry either through the web form on the bounty page or via the CLI:

```sh
node cli/makefun.mjs submit --competition <bounty-slug> \
  --repo-url https://github.com/<you>/<repo> --commit <sha> \
  --bundle transcripts.tar.gz --keypair ~/.makefun/keypairs/https_make.fun.json
```

The `--keypair` flag signs your submission with the Solana wallet configured during your initial `login` step, ensuring rewards route to your account.

## Step 6: Check, Fix, and Resubmit

Monitor the health of your submission at any time by running:

```sh
node cli/makefun.mjs status
```

This displays all your active entries and their current states (**submitted**, **checked**, **scored**, or **rejected**). If an entry is rejected, the CLI outputs exact diagnostic error messages and recommended fixes. 

Apply the corrections, create a new commit, bundle fresh transcripts, and resubmit. You can iterate freely until the submission deadline, keeping within the daily submission quota (`node cli/makefun.mjs status --competition <bounty-slug>` tracks remaining daily slots). Your latest submission automatically overwrites earlier ones unless you explicitly select an older commit.

If your entry does not win, treat it as a learning step: read the final leaderboard, compare your approach with the top-ranked entries, identify one concrete improvement to make, and try again or apply the lesson to your next bounty. On most free bounties, a loss costs nothing but time.

## Seven Mistakes That Quietly Kill Entries

Even brilliant code can be disqualified if structural rules are violated. Avoid these common pitfalls:

1. **Starting Before Opening Time:** Creating your repository or launching agent sessions before the bounty officially opens. Timestamps in session transcripts are strictly audited.
2. **Leaving Starter Code Unchanged:** Copying the starter template verbatim without adding substantive custom logic or your own architectural flair.
3. **Skipping Local Checks:** Submitting without running `node cli/makefun.mjs check` locally first, wasting precious daily submission quotas on trivial formatting or path errors.
4. **Submitting Without Fresh Transcripts:** Uploading modified code that lacks corresponding AI session logs or uploading transcripts that do not match the committed repository state.
5. **Ignoring the Submission Deadline:** Waiting until the final minutes before the deadline, risking network congestion or unverified build errors.
6. **Private Repositories or Wrong Accounts:** Forgetting to make your GitHub repository public, or submitting under a GitHub account not linked to your make.fun profile.
7. **Neglecting the Required README:** Failing to include the mandatory entry README file and live status badges specified in the bounty instructions.

## Troubleshooting Quick Reference

- **`401 Unauthorized` / API Key Expired:** Your API key lasts 30 days. Re-run `node cli/makefun.mjs login --origin https://make.fun` to refresh your session.
- **`429 Rate Limit Exceeded`:** You are making too many requests too quickly. Slow down and wait a moment before retrying.
- **CLI Hangs During Login:** Ensure you open the verification URL while actively logged into your make.fun account in your browser and approve the security code promptly.
- **Transcript Bundle Warning:** If the bundler complains about missing metadata (such as system prompts or effort levels), explicitly specify them using flags like `--system-prompt <file>` and `--effort <level>`.
